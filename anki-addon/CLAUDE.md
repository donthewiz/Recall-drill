# anki-addon/: Recall Drill add-on

Loads when you work in this folder. The full record is `docs/DECISIONS.md` (read the
headings your change touches); `tests/SPEC_MAP.md` maps spec items to tests.

## Layout and layers

| Part | Rules |
|---|---|
| `recalldrill/engine/` | Pure Python port of the TS engine (`src/utils/`). Strict pyright. Behavior changes follow the root CLAUDE.md's "Engine changes" (TS, goldens, Python, one commit) |
| `recalldrill/anki_io/` | May import `anki` and `aqt.operations`, never Qt. Strict pyright |
| `recalldrill/*.py` (top level) | Pure modules: no Qt, mostly no Anki. The strict list is `strict = [...]` in `pyproject.toml` |
| `recalldrill/ui/` | Qt. Standard pyright (PyQt6 stubs leave signals partly Unknown). Colors, sizes and fonts only from `TOKENS` in `ui/style.py`; menu labels are constants at the top of `ui/entry.py` |
| `vendor/` | Trimmed SymPy and mpmath, loaded only through `recalldrill/math_vendor.py` (the one place that touches `sys.path`) |
| `tests/golden/` | Generated by `npx tsx anki-addon/tools/export_golden.ts`; never hand-edited (hook-blocked) |

`tests/test_layering.py` enforces the layers. Add a new pure module to the strict list.

## Collection writes

The add-on writes to the collection in exactly three places: the **handoff**, the
**release** ("Send to Anki undrilled") and **hold back**. Each plans first, then applies
as **one undo step**; on failure the steps that ran are merged into that step and undone;
exact tags only. A new kind of collection write, or a change to what one of these writes,
changes what Don sees in Anki: stop and ask unless the prompt already settles it.

Tags the add-on writes: `rd::drilled`, `rd::hard`, `rd::final-miss`, `rd::holdout`,
`rd::undrilled`, `rd::held` (and `rd::long` when `tag_long` is on). The skill's tags it
reads: `rd::drill::*`, `Layer::N`, `rd::math`, `rd::math::equiv`. Math Path recipe notes
(a note type with both `RecipeId` and `Recipe` fields) are never drilled, held or released
(`select.content_check` reason `math_path`).

## Math answers

`recalldrill/math_parse.py` and `math_answer.py` are also copied, unchanged, into the
anki-math-cards plugin and into `mathpath-addon/core/drill_check/`. If you change either,
say so under "Your to-dos" in the report: the plugin and Math Path's copy must be updated
from it later (never edit Math Path's copy here).

## Tests

- Run from the repo root: `anki-addon/.venv/bin/python -m pytest anki-addon/tests/<path> -q`.
- Tests that import `aqt` skip in CI (`needs_aqt`) but run in the cloud venv, which has
  `aqt`; the drill window runs on Qt's offscreen platform with a stand-in web view
  (QtWebEngine can't start offscreen).
- Anki tests use scratch collections (`tests/anki_io/anki_fixtures.py`), never a profile.
- pytest uses `--import-mode=importlib` (set in `pyproject.toml`).

## Packaging

`python anki-addon/build.py` writes `dist/recall_drill-<version>.ankiaddon`; it refuses a
dirty tree. `tests/test_package.py` keeps `VERSION` in `recalldrill/__init__.py` and the
source `manifest.json` equal. Don loads the add-on through a dev junction, so a merged
change reaches his Anki without a package; don't ask him to install one unless the prompt
does.
